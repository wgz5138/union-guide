## 〇、先讀：本系統有兩個可獨立部署的部分

| 部分 | 程式 | 跑在哪 | 特性 |
|---|---|---|---|
| **A. Google Flights 抓取**（本案核心） | `gflights_scraper.py` | **需要真實瀏覽器的桌機/伺服器** | 真 Chrome＋擬真操作，過反爬最穩 |
| B. API 版查價＋通知（佐證／加值） | `travelpayouts_flights.py` | 任何能連網的機器／GitHub 雲端 | 純 API，輕量、無瀏覽器 |

## 一、系統需求（A：Google Flights 抓取）

| 項目 | 需求 | 說明 |
|---|---|---|
| 作業系統 | Windows 10/11（建議）、或 Linux（需設定虛擬顯示，見第五節） | 開發與實測以 Windows 為主 |
| Python | 3.9 以上 | `python --version` 確認 |
| 瀏覽器 | **建議安裝桌面版 Google Chrome** | 程式優先用真 Chrome（指紋最像真人）；找不到會自動退回內建 Chromium |
| 網路 | 可直連 Google；如需穩定大量抓取，建議**付費住宅代理 IP**（選配） | 代理由委託方自備、費用自負（見維護保固說明） |
| 硬體 | 一般文書機即可；建議 4GB RAM 以上 | 瀏覽器會佔記憶體 |

## 二、安裝步驟（共通，三步）

在專案資料夾 `freelance-flights-mvp/` 下：

```bash
# 1. 安裝 Python 套件
pip install -r requirements.txt

# 2. 安裝 Playwright 的瀏覽器核心（必做，否則開不了瀏覽器）
playwright install chromium

# 3.（建議）另外安裝桌面版 Chrome，程式會優先使用它
#    到 https://www.google.com/chrome/ 下載安裝即可
```

> 完成後資料夾會自動建立 `data/`（輸出與持久設定檔）與 `logs/`（執行日誌）兩個資料夾，**已設定不進版控**（見 `.gitignore`）。

---

## 三、設定（改一個檔就好）

打開 `gflights_scraper.py` 最上方「設定區」，依需求調整：

```python
ROUTES = [
    {"origin": "KHH", "dest": "NRT", "date": "2026-09-15"},  # 高雄→東京
    {"origin": "KHH", "dest": "KIX", "date": "2026-09-15"},  # 高雄→大阪
]

HEADLESS = False     # 建議 False：顯示瀏覽器，過反爬最穩（伺服器無桌面時見第五節）
MAX_TRIES = 8        # 每條航線最多重試次數（高穩定性關鍵，不建議調低）
FETCH_BAGGAGE = True # 是否逐班點進詳情抓「行李額度」（較慢）
BAGGAGE_TOP = 5      # 每條航線最多抓前幾班的行李
```

- **出發/抵達**用 IATA 機場代碼（KHH＝高雄、NRT＝東京成田、KIX＝大阪關西…）。
- **日期**格式 `YYYY-MM-DD`。
- 其餘參數（禮貌間隔、settle 時間）已調校過,**一般不需改動**。

### 代理 IP（選配，臨時被封／大量抓取時才需要）
不必改程式，**設一個環境變數**即可啟用；留空＝直連（預設）：

```bash
# Windows (PowerShell)
$env:GF_PROXY = "http://帳號:密碼@host:port"
# Linux / Mac
export GF_PROXY="socks5://host:port"
```

## 四、執行與驗證（第一次部署必做）

```bash
# 正式抓取（依 ROUTES 設定）
python gflights_scraper.py
```

**成功的判準**（終端機最後一行 log）：
```
=== 完成：成功 2/2 航線（100%），共抓 N 班 ===
```
並確認產出三個檔：
- `data/gflights.csv`（Excel 可直接開，UTF-8-SIG 中文不亂碼）
- `data/gflights.json`
- `logs/gflights.log`（每次執行的明細）

### 驗收用：連續穩定度壓測
產出「成功率」實測數據（驗收標準第三節要求）：
```bash
python 穩定度壓測.py 10 1800     # 跑 10 趟、每趟間隔 30 分鐘
```
結果寫入 `data/stability_test.csv`，可直接作為驗收佐證。

> ⚠️ 間隔請設「數十分鐘以上、貼近實際每日排程」；**高頻連發會觸發反爬限速，所得數據不代表正常運行**（見驗收標準第四節排除條款）。

## 五、Linux / 雲端伺服器部署（無桌面環境）

Google 對 headless 偵測較嚴，本系統以 `HEADLESS=False`（顯示瀏覽器）最穩。
在**沒有桌面的 Linux 伺服器**上，用**虛擬顯示（Xvfb）**讓非 headless 瀏覽器也能跑：

```bash
# 1. 安裝虛擬顯示與相依套件
sudo apt-get update
sudo apt-get install -y xvfb
# 2. 安裝 Playwright 瀏覽器與系統相依
pip install -r requirements.txt
playwright install --with-deps chromium
# 3. 在虛擬顯示下執行
xvfb-run -a python gflights_scraper.py
```

> 伺服器若無法安裝真 Chrome，程式會**自動退回內建 Chromium**（log 會註記）；穩定度可能略降，建議搭配住宅代理 IP。

### 排程（每日自動跑）
- **Windows**：雙擊 `設定Google機票每天自動跑.bat`（用 Windows 工作排程器，附失敗重跑、錯過補跑）。取消用 `取消Google機票排程.bat`。
- **Linux（cron 範例，每天 09:00）**：
  ```cron
  0 9 * * * cd /path/to/freelance-flights-mvp && xvfb-run -a python gflights_scraper.py >> logs/cron.log 2>&1
  ```

## 六、（附）API 版部署（travelpayouts_flights.py）

輕量、無瀏覽器，可跑在任何能連網的機器或 GitHub 雲端：

```bash
pip install requests
# 設定金鑰（環境變數，勿寫進程式）
export TRAVELPAYOUTS_TOKEN=...   # https://www.travelpayouts.com 免費申請
export TG_TOKEN=...   export TG_CHAT=...   # Telegram 推播（選配）
python travelpayouts_flights.py
```
- **雲端每日自動跑**：把上述三個金鑰設為 GitHub repo Secrets，`.github/workflows/flight-prices.yml` 會每天自動執行。

## 七、常見部署問題

| 症狀 | 原因／處理 |
|---|---|
| `playwright: command not found` 或開不了瀏覽器 | 沒跑 `playwright install chromium` |
| Linux 上瀏覽器啟動失敗、缺 .so 函式庫 | 改用 `playwright install --with-deps chromium` |
| 中文在 Excel 變亂碼 | 用支援 UTF-8 的方式開啟；本系統 CSV 已用 `utf-8-sig`，多數情況正常 |
| 一直「載入成功但沒有航班」 | 可能該日該航線無票；或頻率過高被限速（見故障排除 SOP） |
| 權限錯誤（PermissionError） | 別把專案放在系統保護資料夾（如 Windows System32）；放一般使用者目錄 |

> 更多反爬／封鎖／改版類問題，見「**故障排除 SOP**」。
