一、一句話

我已實作一套自動化機票數據抓取系統並實際運行：針對本案的 Google Flights 目標，

以 Playwright 驅動真實 Chrome 瀏覽器，實際抓到指定航線／日期的機票資料

（票價、轉機次數、起降時間、航空公司、行李額度），並輸出結構化 CSV／JSON。

反爬方面採「真實瀏覽器指紋＋擬真人類操作（滑鼠軌跡、hover、逐步捲動、隨機間隔）

＋自動重試」，於近期多趟實測中可穩定取得結果。航班號則因 Google 介面不穩定提供，改以「兩段式增益」補齊：詳情頁有露出就直接抓，抓不到則查內建對照表補入（不依賴任何第三方 API）。

以下逐條對照貴案需求並誠實標示完成度（長期穩定運行仍需維護）。

三、技術棧

  • Python ＋ Playwright（Chromium／優先使用本機真實 Chrome）：處理 JavaScript

動態渲染、模擬真實瀏覽器，並以真實指紋降低被偵測機率

  • 反爬設計：stealth 隱藏自動化特徵、持久化設定檔（保留 cookie／同意）、

擬真人類操作（滑鼠軌跡、hover、逐步捲動、隨機間隔）、自動重試到結果載出

  • 排程：Windows 工作排程器（本機，含失敗重跑／錯過補跑／執行紀錄）
  • 儲存：CSV、JSON（可依需求改資料庫，如 SQLite／MySQL）
  • 穩定性設計：載入與詳情頁重試、逐航線即時存檔、單筆出錯不中斷、日誌輪替、

設定與密鑰分離（環境變數）

四、系統架構

   排程（本機工作排程器；含失敗重跑／錯過補跑／紀錄）
                  │ 定時觸發
                  ▼
   Playwright 開「真實 Chrome」→ 載入 Google Flights（指定航線/日期）
                  │ 等待動態渲染、處理同意視窗、逐步捲動帶出航班
                  ▼
   解析：票價／轉機／時間／航空（→ 逐班點詳情頁補「行李額度」）
                  │ 重試・逾時・日誌・逐航線即時存檔
                  ▼
   結構化儲存（CSV + JSON）
                  │
                  └─（選配加值）降價偵測 → 通知（Telegram／Email）

五、附帶能力（同一份作品集內可佐證）

除 Google Flights 爬蟲外，本作品集亦包含一套以官方資料 API 為來源的機票監測系統

（多航線、降價偵測、雲端每日自動執行、Telegram 雙向查詢），可佐證我對

「抓取 → 整理 → 排程 → 儲存 → 通知」完整鏈路的掌握，以及在「爬蟲」與「API」

兩種資料來源之間的取捨判斷。降價通知／推播屬選配加值，可依委託方需求接入。

六、交付與後續（正式委託時）

  • 依委託方指定之實際航線／日期清單校準與擴大驗證
  • 航班號：以「詳情頁直抓＋內建對照表」補齊（已內建，不依賴第三方 API）；如需更大覆蓋可再評估接班表來源
  • 依抓取量級加上反爬強化（代理 IP 已內建選配，可即時啟用；另可加頻率控制、失敗告警）
  • 交付：原始碼 + 使用說明 + 部署／排程設定；可議定維護範圍
  • 合規提醒：目標網站服務條款多禁止自動抓取，建議一併評估頻率、封鎖與法律風險，

必要時改用官方／授權資料來源。
