## 〇、通用診斷起手式（先做這三步）

遇到任何異常，先做這三件事再對照下方分類：

1. **看日誌**：打開 `logs/gflights.log`，找最後幾行的 `[WARNING]`／`[ERROR]`，那通常直接寫出原因。
2. **看成功率**：終端機最後一行 `=== 完成：成功 X/Y 航線（Z%）===`，判斷是「全掛」還是「部分失敗」。
3. **單跑一條航線**：把 `ROUTES` 暫時只留 1 條再跑，縮小範圍、快速重現。

> 判斷原則：**偶發、部分失敗、重跑會好** → 多半是目標網站暫時抽風（正常，系統會自動重試）；
> **持續、全部失敗、怎麼跑都壞** → 往「改版／封鎖／環境」三大類查。

## 一、IP 被封鎖 / 觸發反爬限速

### 典型症狀
- log 反覆出現「系統發生錯誤」、「載入嘗試 8/8 仍未載出」。
- 頁面長時間轉圈、空白，或要求人機驗證。
- **換一條網路（如手機熱點）就正常** → 高度指向 IP 被限。

### 研判
- 最近是否**短時間內大量／高頻**執行？（最常見主因）
- 是否多台機器／多排程**共用同一對外 IP**？

### 應變步驟（由輕到重）
1. **降頻＋等待**：停止執行,**間隔數十分鐘以上**再跑；輕度限速通常數小時內自行解除。
2. **拉長排程間隔**：確認每條航線間隔貼近「每日排程」節奏,勿高頻連發。
3. **換對外 IP**：重啟數據機/路由器（浮動 IP 會換）、或換一條網路測試。
4. **啟用代理 IP（選配，最有效）**：設環境變數即可，無需改程式：
   ```bash
   # Windows
   $env:GF_PROXY = "http://帳號:密碼@host:port"
   # Linux / Mac
   export GF_PROXY="socks5://host:port"
   ```
   - **建議用付費住宅（Residential）代理**；免費/資料中心代理多半也會被封，效果有限。
   - 代理服務由**委託方自備、費用自負**（見維護保固說明第六節）。

### 權責歸屬
- 降頻、換 IP、買/設代理 → **委託方可自行處理**（本 SOP 已足夠）。
- 若**已正常頻率＋已用住宅代理仍持續被封**，屬反爬升級 → **有償維護**（見維護保固第三節）。

## 二、網站結構微調 / 改版

### 典型症狀
- **持續、全面**抓不到資料，但**頁面本身用瀏覽器手動打開是正常的**。
- 抓到的某欄位**整批變空或明顯錯亂**（例如價格全空、航空全空、時間錯位）。
- 改版常發生在 Google 更新介面之後,且**換 IP 也沒用**（與封鎖的關鍵區別）。

### 研判：先區分是「改版」還是「封鎖」
| 線索 | 比較可能是 |
|---|---|
| 手動開頁正常、程式整批抓不到/欄位全空 | **改版** |
| 手動開頁也常出錯、要求驗證、換 IP 就好 | **封鎖/限速**（回第一節） |

### 第一線可自助確認
1. 用瀏覽器手動打開 log 裡的查詢網址，確認頁面**結構/欄位是否與以往不同**。
2. 檢查是哪一類欄位失效：
   - **價格/時間/航空全空** → 列表卡或解析規則需重新校準。
   - **只有行李/航班號抓不到** → 詳情頁結構變動（屬加值項，影響較小）。

### 應變
- 改版導致的**選擇器/解析規則重新校準，屬程式維護工作**，需開發方處理。
- 委託方請提供：① 失效的航線/日期、② log 片段、③ 手動開該網址的截圖。
- 處理方式與計費見「維護保固與責任說明」第三、四節（**目標網站改版屬有償維護**）。

> 設計上已盡量抗改版（靠內容特徵而非亂碼 class 定位），但**大幅改版仍需校準**——這是所有爬蟲的本質,非程式瑕疵。

## 三、驗證碼（CAPTCHA）卡關

### 典型症狀
- 頁面跳出「請證明你不是機器人」、圖形/勾選驗證。
- log 顯示載入重試多次仍未通過、頁面停在驗證畫面。

### 研判
- 驗證碼幾乎都是**反爬被觸發**的結果 → 根因通常與第一節（IP/頻率）相同。

### 應變步驟
1. **首選——人工通過一次（利用持久設定檔）**：
   - 確認 `HEADLESS = False`（看得到瀏覽器）。
   - 執行程式，當驗證碼出現時**手動點過**；因系統使用持久設定檔 `data/.gf_profile`,
     **通過後的狀態會被記住**，後續較不會反覆跳驗證。
2. **降頻**：驗證碼頻繁出現＝被判定可疑 → 拉長間隔、降低執行頻率（同第一節）。
3. **換 IP／用住宅代理**：分散來源可降低被要求驗證的機率。
4. **避免 headless**：headless 較易被要求驗證；伺服器無桌面時改用虛擬顯示（Xvfb，見部署說明第五節）而非單純 headless。

### 權責歸屬
- 上述自助步驟（人工過一次、降頻、換 IP/代理）→ **委託方可自行處理**。
- 若 Google **新增了程式無法自動處理的驗證機制**（屬反爬升級）→ **有償維護**，
  且**沒有任何爬蟲能保證 100% 自動繞過驗證碼**（見維護保固第九節）。

> ⚠️ 提醒：本系統**不做、也不建議**自動破解驗證碼（涉服務條款與法律風險）；策略一律是「降低觸發機率＋必要時人工通過一次」。

## 四、其他常見故障速查

| 症狀 | 可能原因 | 處理 |
|---|---|---|
| 開不了瀏覽器 / `playwright` 報錯 | 沒安裝瀏覽器核心 | 跑 `playwright install chromium`（Linux 用 `--with-deps`） |
| 「載入成功但沒有航班」 | 該日該航線**真的無票**，或被限速 | 換日期/航線驗證；若全航線皆無→查限速（第一節） |
| 行李/航班號常為空 | 詳情頁間歇報錯（**正常**，屬加值項） | 不影響清單與成功率；可調小 `BAGGAGE_TOP` 加快 |
| 中文在 Excel 亂碼 | 編碼開啟方式 | CSV 已用 `utf-8-sig`，用支援 UTF-8 的方式開啟 |
| PermissionError 寫檔失敗 | 專案放在系統保護目錄 | 移到一般使用者目錄（勿放 System32） |
| 排程沒跑 | 工作排程器/cron 設定或關機 | 檢查排程設定；雲端 GitHub 排程 60 天無提交會自動停用，手動 Run 一次即可 |
| log 檔變很大 | — | 已設自動輪替（單檔 1MB×3 份），無需手動清 |

## 五、何時該找開發方（界線一覽）

| 情況 | 歸屬 |
|---|---|
| 降頻、換 IP、買/設代理、人工過一次驗證碼、環境安裝 | **委託方自助**（本 SOP 已涵蓋） |
| 程式自身 bug（保固期內、網站未改版） | **免費保固**（維護保固第二節） |
| 網站改版、反爬升級、新增驗證機制、規模擴充、需求變更 | **有償維護**（維護保固第三、四節） |
| 第三方（代理/API/主機）費用與可用性 | **委託方負擔** |

### 回報故障時請附上（加速處理）
1. 發生時間、影響的航線/日期。
2. `logs/gflights.log` 最後 30–50 行。
3. 終端機最後的「成功率」那行。
4. 手動用瀏覽器打開該查詢網址的**截圖**（判斷改版/封鎖的關鍵）。
