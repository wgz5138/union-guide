## 一、整體架構

```
┌──────────────────────── gflights_scraper.py（核心）─────────────────────────┐
│                                                                             │
│  設定區(ROUTES) → 建網址 → [載入重試] → [列表解析] → [逐班詳情加值] → [儲存]   │
│       │            build_url   load_with_retry  extract        save          │
│       │                          │  page_loaded_ok  parse / parse_baggage    │
│       │                          │                  parse_flight_no          │
│       └── 代理(選配) build_proxy ─┘                                           │
│                                                                             │
│  橫切：擬真操作(human_click/scroll) · 指數退避(_backoff) · 日誌(logging)        │
└─────────────────────────────────────────────────────────────────────────────┘
        │                         │                          │
        ▼                         ▼                          ▼
   data/gflights.csv      data/gflights.json          logs/gflights.log
   （結構化輸出，累加）     （結構化輸出，累加）          （每次執行明細）

   穩定度壓測.py ──呼叫──> gflights_scraper.main() ──> data/stability_test.csv（成功率佐證）
```

**技術選型**
- **Python 3** + **Playwright（同步 API）** 驅動**真實 Chrome**。
- 選 Playwright 而非 requests/BeautifulSoup：Google Flights 是重度 JavaScript 動態頁面，
  價格與航班卡都是前端非同步渲染，**必須用真實瀏覽器**才能取得完整內容。
- 輸出採 **CSV（UTF-8-SIG）＋ JSON** 雙格式，皆為**累加**寫入（保留歷史）。
- 日誌採 `RotatingFileHandler`（單檔上限 1MB、保留 3 份備份），自動輪替不爆磁碟。

## 二、爬蟲定位邏輯（如何精準抓到資料）

### 1. 用「預填搜尋」的網址直達結果頁
不模擬人手一格格填表單，而是用 Google Flights 支援的查詢字串網址直接帶出結果：
```
https://www.google.com/travel/flights?q=Flights from KHH to NRT on 2026-09-15 oneway
   &curr=TWD&hl=zh-TW&gl=TW
```
→ 一個網址就鎖定「航線＋日期＋幣別＋繁中介面」,**穩定、可重現**。（`build_url()`）

### 2. 用「內容特徵」找航班卡，不靠會變的 class
Google 的 HTML class 是**動態亂碼、隨時會變**，若綁死 class，網站一改版就全壞。
本系統改用**內容特徵**定位：掃描頁面所有 `<li>`，凡同時包含
**「$價格（3 位數以上）」與「小時／分鐘」**者，判定為一張航班卡。（`extract()`）
→ 這種定位**對改版的耐受度遠高於綁 class**。

### 3. 用「正則表達式」從卡片文字解析欄位（`parse()`）
從每張卡的純文字中抽出結構化欄位：

| 欄位 | 解析方式 |
|---|---|
| **票價** | 抓 `$` 後數字或千分位數字 → 去逗號轉整數 |
| **轉機次數** | 「直達/直飛/nonstop」→ 0；「轉機 N 次／N stop」→ N |
| **起降時間** | 抓中文時制（清晨/上午/中午/下午/晚上/凌晨＋h:mm），取前兩個**相異**時間為出發/抵達；偵測跨日「+1」補在抵達後 |
| **航空公司** | 先比對內建台日韓主要航空中文名清單；找不到再後備抓「⋯航空」字樣 |

### 4. 加值資料：逐班點進「詳情頁」（`click_flight` → `fetch_detail_text`）
- **行李額度**：點開航班卡 → 等「手提行李／託運行李」字樣出現 → 解析（`parse_baggage`）。
- **航班號**：詳情頁若有露出（格式如 `UA 838`）就抓（`parse_flight_no`，依航空 IATA 代碼精準比對）。
- 列表為**虛擬捲動／lazy-load**，下方卡片可能尚未進 DOM →
  以「價格＋出發時間」為鍵，**邊往下捲邊找**把卡片逼出來再點。

> ⚠️ 詳情類資料（行李、航班號）為**加值項**：詳情頁本身會間歇報錯，故採「盡力取得、失敗不影響清單」，**不納入成功率主指標**（見驗收標準）。

## 三、反爬蟲應對機制（如何降低被偵測／封鎖）

本系統以「**讓自動化看起來像真人**」為核心策略，多層並用：

| 機制 | 實作 | 作用 |
|---|---|---|
| **真實瀏覽器指紋** | 優先用桌面版真 Chrome（`channel="chrome"`），其 WebGL/字型/codec 即真瀏覽器 | 比內建 Chromium 更不易被識破 |
| **stealth 隱藏特徵** | 注入 JS 隱藏 `navigator.webdriver`、偽裝 languages/plugins/chrome 物件（`STEALTH_JS`） | 消除最明顯的自動化痕跡 |
| **持久化設定檔** | 重用 `data/.gf_profile`，保留 cookie 與同意狀態 | 不必每次重新被當「全新可疑訪客」 |
| **關閉自動化旗標** | 啟動參數 `--disable-blink-features=AutomationControlled`、移除 `--enable-automation` | 降低被偵測機率 |
| **本地化情境** | locale `zh-TW`、時區 `Asia/Taipei`、固定視窗大小、台灣 UA | 情境一致，較像真人 |
| **擬真操作** | `human_click`（捲到可視→滑鼠帶軌跡移動→hover→微停→才點）、`human_scroll`（分段捲動、隨機停頓、偶爾回捲） | 行為節奏像人，不瞬移、不機械式 |
| **禮貌間隔** | 班與班之間隨機等 1.5–3.5 秒（`POLITE_WAIT_MS`） | 降低觸發限速、較耐封 |
| **同意視窗處理** | 自動點掉多語系同意/cookie 牆（`CONSENT_LABELS`） | 避免卡在同意頁 |
| **代理 IP（選配）** | 設 `GF_PROXY` 即啟用（`build_proxy`），支援 http/socks5/帳密 | 臨時被封或大量抓取時分散來源 |

> **誠實聲明**：以上機制可**顯著降低**被偵測/封鎖機率，但**任何爬蟲都無法保證**永不被封、永久可用、速率不受限。詳見「維護保固與責任說明」第一、九節。

## 四、錯誤回復流程（高穩定性的核心）

系統的「高穩定性」來自**多層級的失敗自動回復**，任何單點失敗都不會中斷整體：

### 第 1 層：單次載入重試 ＋ 指數退避（`load_with_retry` / `_backoff`）
- 每條航線最多重試 `MAX_TRIES=8` 次。
- goto 逾時、frame detached 等例外 → **記 log、退避等待、繼續重試**，絕不外拋。
- 退避時間隨次數拉長（`2.5s × 次數`，上限 12s），更能熬過暫時性故障。
- 後段嘗試（≥3 次）會輕推捲動，逼出 lazy-load 內容、提高命中率。

### 第 2 層：嚴格的「載入成功」判定（`page_loaded_ok`）
- 必須**同時**看到「價格」與「小時（航程時長）」、且**無錯誤字樣**才算載出。
- 避免「頁面剛開、還沒載完」就被誤判成功而抓到空資料。

### 第 3 層：詳情頁自動重載（`fetch_detail_text`）
- Google 詳情頁會間歇出現「系統發生錯誤」→ 自動點「重新載入」或 `reload`，最多 5 輪。
- 加 settle 等待避免把「載入瞬間」誤判成錯誤；仍失敗則**放棄該班、不影響其餘**。

### 第 4 層：逐班防呆（`extract` 內 try/except）
- 任何一班抓行李/詳情出錯 → 只略過該班並嘗試回到可用列表，**不中斷整條航線**。

### 第 5 層：航線層防呆（`try_one`）
- 單一航線任何未預期錯誤 → 只記 log、回傳失敗，**不影響其他航線**。

### 第 6 層：第二輪補救（`main`）
- 第一輪失敗的航線，全部跑完後**再給一次機會**（Google 常只是暫時抽風）。

### 第 7 層：抓完即存（`save`）
- **每抓完一條航線就立即寫檔**，即使後續中途崩潰，已抓到的資料也不會遺失。

> 結果：即使部分航線/班次暫時失敗，系統仍能盡可能完成其餘工作、保留已得資料，並在 log 與最終「成功率」統計中如實反映。

## 五、資料輸出規格

每筆航班資料（CSV/JSON 欄位）：

| 欄位 | 說明 |
|---|---|
| `scraped_at` | 抓取時間戳 |
| `query_date` | 查詢日期 |
| `origin` / `dest` / `date` | 出發/抵達機場代碼、出發日期 |
| `price_twd` | 票價（新台幣，整數） |
| `transfers` | 轉機次數（0＝直飛） |
| `depart_time` / `arrive_time` | 出發/抵達時間（抵達含跨日「+N」） |
| `airline` | 航空公司 |
| `flight_no` | 航班號（詳情頁有露出才填，否則空） |
| `baggage` | 行李額度（前 N 班加值，否則空） |
